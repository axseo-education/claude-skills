# /critique — 다각도 비평 + PM 머지

## 한 줄

**결과물 1개**를 N명 비평 워커가 서로 다른 관점에서 까고, 메인이 PM으로 P0/P1/P2 머지.

## 언제 쓰나

- 코드 변경 후 출시 전 점검
- 페이지/HTML 결과물 사전 검수
- 카피/광고 소재 컴플라이언스+후킹 체크
- 스킬/문서 작성 후 갭 점검
- 회의록/녹취록 누락 검토

## 언제 안 쓰나 (다른 스킬 사용)

- 2개 이상 결과물 중 우승작 선택 → **/tournament**
- 여러 작업을 동시 생성 → **/orchestra**
- DDL/보안/인증/API 계약 등 고위험 변경 → **우로보로스** (Codex 3중 병렬 교차검증)

## 호출

```
/critique [대상]              # 기본 3명
/critique [대상] 5            # 5명
/critique --hard [대상]       # 5명 + 더 빡세게
/critique --auto [대상]       # P0 자동 머지 (위험, 확인 후)
/critique                     # 직전 결과물 자동 검출
```

대상 형식:
- URL: `https://...`
- 파일/디렉토리: 절대 또는 상대 경로
- 텍스트: 따옴표로 감싸기 `/critique "다이어트 7일 -3kg"`
- 생략: 직전 메시지/결과물 추론

## 실행 순서

### Step 0. RUBRIC 자동 감지 (선택)
- 대상 경로에서 상위로 올라가며 `RUBRIC.md` 탐색 (git root 또는 `~`까지)
- 발견 시 → 워커 프롬프트에 자동 첨부 (프로젝트 룰 위반을 콕 짚는 비평)
- 미발견 시 → 일반 비평 진행 + PM 머지 결과에 1줄 안내
- 상세: `_shared/lib/critique-core.md` 참조

### Step 1. 대상 식별 + 관점 분배
1. 대상 종류 자동 판별 (코드/UI/문서/카피/회의록)
2. `_shared/lib/critique-core.md`의 관점 매핑 테이블 참조
3. N명에게 영역 분배 (MECE 강제, 중복 금지)
4. 모호하면 사용자에게 1번만 질문

### Step 2. 워커 병렬 실행
- 단일 메시지에 N개 Agent tool 호출
- 모델: **opus** (judgment 카테고리)
- 각자 `_shared/lib/critique-core.md`의 워커 프롬프트 템플릿 사용
- 200단어 cap, P0/P1/P2 분류 강제

### Step 3. PM 머지 (메인이 직접)
1. **모든 결과 도착 후** 시작 (조기 진행 금지)
2. 중복 제거 (2명 이상 = 신뢰도 ↑ 표시)
3. 우선순위 통합 (높은 쪽 채택)
4. 충돌 감지 + 명시 ("워커 A는 X, 워커 B는 반대")
5. PM 결정 + 1줄 근거

### Step 4. 액션 실행
- **자동 적용 가능** (코드 수정 명확) → 머지 진행
- **사용자 확인 필요** (방향성) → 옵션 제시 후 대기
- **백로그** (당장 불가) → 별도 정리

`--auto` 플래그면 P0만 자동 적용 후 사용자에게 변경사항 보고.

## 출력 포맷

```markdown
## 통합 우선순위 (중복 제거)

### ✅ P0 (즉시 머지)
- [N명 동의] [파일:라인] 항목 — 수정안

### ⏳ P1 백로그
- [N명] 항목 — 작업량 추정

### ⏳ P2 후순위
- 항목

### 🔀 워커 충돌
- 항목 X: 워커1 A 주장, 워커2 B 주장 → PM 결정: A (이유)

### 🛠 적용 결과
- ✅ 머지 완료: N건
- ⏳ 사용자 확인 필요: M건
- 📋 백로그: K건
```

## 핵심 원칙

`_shared/lib/critique-core.md` 참조 (냉정 강제 / MECE / 포맷 고정 / 단어 cap / PM 머지).

요약:
1. 워커 프롬프트에 **"칭찬 금지"** 명시
2. 각 워커가 **다른 영역** (UX vs 데이터 vs 코드 같은 식)
3. **P0 5개 초과 금지** (진짜 블로커가 묻힘)
4. **자동 머지는 --auto 플래그만**

## 안티패턴

- ❌ 워커 결과 받기 전 PM 머지 진행
- ❌ 3명 다 같은 영역 비평 (의미 없음)
- ❌ 칭찬 서두 ("전반적으로 잘 짜여 있으나...")
- ❌ 모호한 표현 ("더 명확하면 좋겠다")
- ❌ 사용자 확인 없이 코드 자동 변경 (--auto 제외)
- ❌ N>5 (의견 노이즈, 머지 부담)

## 다른 스킬과 조합

```
# 카피 생성 → 우승작 선택 → 마지막 검수
/orchestra "신제품 카피 5개" 
  → /tournament copy-1 ~ copy-5 
  → /critique 우승작

# 페이지 빌드 후 점검
/build phase3 
  → /critique apps/web/app/X/page.tsx

# 회의 녹취록 처리 후 누락 체크
/recap meeting.txt 
  → /critique recap-output.md
```
