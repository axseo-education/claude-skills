# naming — 브랜드·제품명 설계 엔진

신규 브랜드명의 최대 비용은 **인지 구축비**다. 이 엔진은 이미 소비자 머릿속에 지어진 인지 자산에 얹어 그 비용을 깎는 작업을 운에서 **설계**로 바꾼다.

**핵심 명제** — 상표법의 유사 판단(분리관찰·지정상품·주지성)과 소비자의 음성 연상은 **다른 층위**에서 작동한다. 그래서 **연상은 넘어오되 법적 유사는 성립하지 않는 안전지대**가 실재하고, 이 엔진은 그 틈새를 의도적으로 조준한다.

## 호출
```
/naming [카테고리] [타깃] [핵심 베네핏]
```
- `/naming 쿠션 30후반~40대 물광` — 후보 10~15 → 게이트 → 채점 → 상위 3
- `/naming` 단독 — 입력 스펙(아래) 문답으로 채운 뒤 실행

**명명 대상(브랜드/제품/라인)은 분기가 아니라 배치 결정**이다. 한 번 생성해 후보를 뽑고 3층 중 어디에 놓을지는 나중에 정한다.

## 입력 스펙
| 항목 | 필수 | 비고 |
|---|---|---|
| 카테고리 | ✅ | 서술어 풀이 여기서 갈린다 |
| 타깃 | ✅ | 착지어 친숙도 판정 기준 |
| 핵심 베네핏 (1·2순위) | ✅ | 1순위가 서술어 어근이 된다 |
| 회피 원본 | ⬜ | 경쟁사·소송 이력 보유처 |
| 확장 계획 | ⬜ | 라인 확장이면 어미 통일 필요 |

## 실행 절차

1. **캘리브레이션 로드** — `~/.claude/naming-lab/calibration.md`를 **먼저 읽는다.** 준석 판정 누적으로 심미 축이 교정돼 있다. 안 읽으면 이 엔진의 핵심이 죽는다.
2. **계보 결정** — `patterns/generation-formulas.md` §계보. 카테고리가 자명한 레드오션이면 **계보 B(F0)**, 설명이 필요한 신규 개념이면 계보 A(F1).
3. **전이 자산 1문장 박제** — 무슨 연상을 가져올지 한 문장. 이후 모든 단계는 이 문장에만 복무한다.
4. **서술어·착지어 풀 깔기** — `tokens/word-pools.md`. **서술어 풀은 카테고리마다 새로 깐다** (쿠션의 두드림·머금음은 파운데이션에 없다).
5. **후보 생성 10~15** — 공식별로. `patterns/generation-formulas.md`
6. **하드 게이트 1차 컷** — `references/legal-gates.md` (상표 3조건·지명·별명층 배치) + 검색 잠식
7. **채점** — `RUBRIC.md`. 하드게이트 4축 중 하나라도 2점 이하면 총점 무관 탈락
8. **산출** — 상위 3 + 각 3층 세트 + **각 후보의 2차 제약을 스스로 먼저 명시** + 다음 검증 액션
9. **축적** — 런 결과를 `~/.claude/naming-lab/<카테고리>/<YYYY-MM-DD>.md`로 Write
10. **캘리브레이션 갱신** — 준석 판정이 오면 `calibration.md`에 1행 추가 (날짜/케이스/판정/엔진판정/델타→반영)

## 원칙
- **계보를 섞지 마라.** 섞으면 계보 A의 리스크(상표·배신·2인자 고착)를 계보 B의 이득 없이 떠안는다. 계보 B에서 의미를 맞추려 하면 즉시 계보 A로 새어나간다 — 실제로 그렇게 샌 이력이 있다
- **심미는 tie-breaker가 아니라 입장 조건.** 못 넘으면 나머지 축은 계산할 가치가 없다
- **차용은 유입 비용 할인 쿠폰이지 제품력 대체재가 아니다.** 첫 구매까지만 유효하고 재구매는 제품이 만든다
- **점수는 실측이 아니다.** 상표·검색은 키프리스·검색 조회 전까지, 회상·친숙도는 실측 전까지 전부 추정치임을 보고에 명시할 것 (Iron Law)
- **최고점 후보의 2차 제약을 스스로 먼저 적어 제출**한다. 점수로만 적고 넘어가지 않는다
